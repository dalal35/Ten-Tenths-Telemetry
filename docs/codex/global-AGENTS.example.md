# Personal development preferences (merge selectively)

Inspect existing code and callers before changing behavior. Preserve unrelated
work and follow the repository's architecture. Prefer reuse and the smallest
complete solution; avoid speculative options, dependencies and abstractions.
Test meaningful changes with focused checks. Report evidence and limitations.
Finish authorized work without repeatedly asking for routine confirmation.
Communicate concisely and end with any skipped checks and material risks.

Use applicable installed skills automatically, within their intended scope.
For library/framework/SDK/API/CLI/cloud documentation, use Context7: resolve the
library ID first, then query one concept at a time, preferring authoritative and
version-matching sources. Do not retrieve library docs for ordinary business
logic, refactoring or review. If unavailable, disclose it and use official docs.

Keep credentials, local trust, personal plugins and machine paths outside source
control. Respect each machine's permissions and the user's current request.
