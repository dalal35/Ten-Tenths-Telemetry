# Production migration roadmap

No production migration is included in this branch. Keep this exploration available as a reference and choose the final direction after hands-on review. The website follows the accepted desktop identity; its implementation is a later phase.

| Phase | Work and existing owners | Acceptance and rollback |
|---|---|---|
| 0 — Agree and measure | Review the three live studies; choose tokens and density. Record real tasks, long sessions and supported text/DPI settings. Measure current native plot/video/inference behavior. | Confirm a direction and representative workflows. Preserve screenshots and baseline performance before changing production. |
| 1 — Foundations and shell | Introduce scoped tokens/font roles. Adapt `Brand`, `motion.tsx`, `App.tsx` shell, `SessionSidebar` and workspace tabs. Preserve `workspaceNavigation.ts`, serialized workspace saves and mounted view identities. | Focused navigation/sidebar verifiers, keyboard/focus checks and visual snapshots at 600×500, 1024×768, 1440×920 and wide desktop. Introduce an independently reversible style/theme layer; retain the current UI during rollout. |
| 2 — Telemetry comparison | Apply chart styling to existing uPlot, `Track`, `Segments` and shared cursor. Improve corner selection, units and toolbar hierarchy without changing analysis requests or calculations. Add a deliberate track-focus layout only if useful in review. | Existing plot/canvas tests plus synthetic cursor/selection checks and private-recording acceptance when available. Compare units, gaps, calibration, alignment and uncertainty against baseline. Roll back styling/layout independently. |
| 3 — Library, import and settings | Refine explorer density, empty/error/import states and contextual settings. Preserve Locate/Refresh/Remove, source-qualified merge identities, confirmation and library persistence. Decide whether settings deserve a consolidated surface after mapping existing owners. | Focused workflow/library tests; real dialogs, drag/drop, Unicode/UNC paths and source changes on Windows. Removing an entry must never delete recordings. No new storage format for visual changes. |
| 4 — Advanced analysis | Restyle `Advanced` and `AnalysisCanvas` tool navigation, presets, formulas and inspectors. Retain active flags, 100ms debounce, zoom and source/channel identities. | Affected advanced/canvas tests and formula/unsupported-channel cases. Confirm background analysis does not run merely because a hidden surface exists. |
| 5 — Video | Refine attachment, empty state, manual sync, segment mapping and playback controls in `src/video/`. Preserve mounted players, pause-when-inactive behavior and current sync contracts. | Existing video verifier plus actual local codecs, YouTube/cache behavior and manual offsets on target OS. Automatic sync remains isolated on `feature/auto-video-sync`; do not merge or expose it through a UI-only change. |
| 6 — AI Coach | Apply evidence-first hierarchy to `coach/`. Clarify measured, modeled, potential and hypothesis sections; refine progress/cancel/error/model setup states. | Preserve model terms, single active inference, cancellation, cache, validation and original-recording restrictions. Native local inference acceptance is separate from browser UI tests. No numerical or causal claims invented by text styling. |
| 7 — Website | Extend the accepted type/color/motion language through `website/`, keeping its narrative and browser-demo disclosure. Reuse authentic app fragments and local assets. | `build:website` and relevant website verifiers; desktop/mobile rendered review, reduced motion, downloads and synthetic-demo boundaries. No publishing without the user's deployment request. |
| 8 — Native release readiness | Review end-to-end import → compare → advanced/video/coach → reopen. Test native Windows WebView2 and macOS WebKit with real data and accessibility tooling. | Target-OS media/inference checks, keyboard and screen readers, 125/150/200% Windows DPI, short/wide windows, slow operations and low-end hardware. Only then schedule packaging/release as a separate authorized action. |

## Engineering boundaries

Keep calculation, authorization, backend and persistence contracts stable throughout these visual phases. Reuse the existing libraries and controls before adding dependencies. Do not transplant the prototype's SVG renderer, synthetic-data helpers or centralized local demo context into the production analysis engine.

Each phase should be a small reviewable branch with its affected checks and screenshots. Separate visual acceptance from native correctness. A browser pass cannot establish WebView2 codecs, macOS framework behavior, local inference quality or installer parity. No broad test suite is required merely to evaluate these prototypes; production migrations need the owner's focused regression coverage.
