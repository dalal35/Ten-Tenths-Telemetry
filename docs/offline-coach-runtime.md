# Offline coach runtime and model distribution

The installed app links llama.cpp through pinned `llama-cpp-2 = 0.1.160`. There is no HTTP client, external service, Python process, shell invocation or model downloader in the inference path. The Node provisioning script runs only on the build host. Apple Silicon uses the binding's built-in Metal backend; other supported builds use CPU unless a backend is compiled. An acceleration load/context/decode failure retries CPU after dropping the failed instance.

The worker reads a fixed packaged `resources/coach/model.gguf`, verifies its SHA-256 by streaming, and lazily loads it. The inference mutex prevents concurrent model instances. Each request drops its sampler, context, weights and backend on success, error or cancellation; no weights remain resident intentionally while idle. Cancellation/deadline is checked before load, during integrity reads, between prompt chunks and each generated token. A single native load/decode operation cannot be interrupted by Rust checks; cancellation latency therefore depends on that operation. Prompt context is capped at 6144 tokens, generation at 768 tokens, generated insights at three, prompt evaluation batches at 128 and CPU threads at four with capacity reserved for ordinary UI work. A 90-second checked deadline provides a fallback trigger, not a hard real-time process kill or RAM cap.

The model receives compact validated section summaries and the deterministically selected primary opportunities, never recording files. Production inference compares bounded candidate-specific interpretations: a technique hypothesis, a competing entry/load explanation, and a conditions/alignment or repeatability explanation. Gemma emits only supplied opportunity and interpretation IDs in its chosen order. Rust maps those IDs to vetted hypotheses, specific experiments and verification text; source metadata identifies this as `modelSelectedInterpretation`. The model may abstain. It cannot change membership of the compatible numerical budget or author a numerical gain. Strict grammar and typed validation reject extra fields, duplicate/invented IDs and unoffered choices. The UI explicitly discloses model selection rather than attributing authored wording or calculations to Gemma. This boundary prevents fabricated facts but does not establish that every selected interpretation is the best coaching decision. Legacy free-prose diagnostics remain guarded and are not the production recommendation path. The computed report remains available when inference fails or reaches its resource limit.

CPU fallback explicitly selects an empty GPU device list and disables context KQV/operation offload. Merely requesting zero GPU model layers was insufficient: early CPU-labelled benchmarks still allocated Metal context buffers. That defect was corrected and the true CPU path completed with networking and GPU access denied by the execution sandbox.

## Analysis and integration

`analysis.rs` owns versioned facts and quality decisions; `types.rs` is the serialized frontend contract. Spatial comparison uses the existing telemetry engine in a canonical partition of the automatically selected fastest valid lap. Other laps provide supporting section examples rather than becoming coaching targets. Outlaps/inlaps with incomplete crossings and invalid durations are excluded. Recording completeness alone cannot identify pit intent. Theoretical timing requires complete compatible coverage and actual segment sources, and substitutions must exceed measurement uncertainty. Nonoverlapping sections are counted once; the composite is an analytical reference, not a guaranteed achievable lap. Boundary speeds and interactions between sections limit how recorded segments can be combined.

The fastest lap is also screened for signal-based inefficiencies when no faster recorded example exists. Every corner and straight retains its measured evidence and data limitations. Measured opportunities require a faster valid spatially aligned example above timing uncertainty. Repeated supporting entry/apex/exit speed tradeoffs can be likely improvements even below stopwatch resolution; single examples and sustained fastest-only apex recovery remain areas to investigate. Neither qualified tier carries a measured numerical gain. Separately labeled hypothetical scenario ranges can be calculated from valid recorded speed profiles; see [per-suggestion time estimates](coach-time-estimates.md). These remain distinct from measured differences; only endpoint-preserving, acceleration- and geometry-screened scenarios can contribute once to the full-lap enhanced budget. Normal braking is not treated as proven inefficiency, and an exit advantage inherited from substantially faster entry is excluded from tradeoff recommendations. Low-RPM screening uses a relative recording-derived threshold, not a validated engine powerband or confirmed bogging diagnosis. Missing controls, calculated gear, GPS uncertainty and signal gaps constrain the advice. RPM, shift and speed observations do not receive additional numerical time gain on top of the same section difference.

`Library::coach_input` validates the source content and snapshots session/boundaries before releasing the library mutex. `commands.rs` runs analysis and inference off the UI thread. `service.rs` owns a single active job, cancellation identity and a four-result memory cache. Its identity includes content digest, the fastest-lap analysis scope, persistent corner boundaries, analysis version, model version/digest and model terms acceptance. The cache also includes the reasoning protocol version. Cached explanations are reused until one of these changes; regeneration reuses cached facts. Legacy target arguments are ignored and do not affect cache identity. Results are not persisted across app restarts.

The improvement objective is automatic. Deterministic analysis selects compatible, non-overlapping opportunities and returns their ranges and an enhanced theoretical lap range. Traditional sector support stays separate. See [gain methodology](coach-time-estimates.md).

The coach is a workspace, not a chat surface. It analyzes the fastest valid lap when opened and displays at most three distinct actionable findings. The main view shows fastest lap, enhanced theoretical best, estimated improvement potential, and a single Analyze action. Each card shows its range or an explicit unquantified label, a concise experiment and verification instructions. Raw measurements, assumptions, comparison quality, traditional theoretical calculations and warnings remain expandable. Per-card labels distinguish computed coaching from local AI interpretation; global status distinguishes inactive AI, fallback, generated and cached output. Evidence inspection enables available speed and RPM channels, selects the fastest lap, optionally overlays a supporting example, maps the recording interval through the fastest lap's own position mapping, focuses plots/GPS, and seeks compatible attached video when the player becomes ready. Missing footage does not delay telemetry focus. Native YouTube remains unsupported by the existing application. Cross-recording merged coaching is explicitly unavailable; original recordings remain fully supported.

## Build and packaging

`node scripts/prepare-coach-model.mjs --download` provisions the pinned public Gemma 3 1B instruction Q4_K_M GGUF on the build machine. `node scripts/prepare-coach-model.mjs` verifies size, digest and notices without networking. The 806,058,240-byte artifact is intentionally ignored by Git, and must be provisioned before packaging. Its revision, URL, byte count and digest are recorded in `src-tauri/resources/coach/manifest.json`. The installer must include the entire coach resource directory. This makes the installed product fully functional offline; there is no first-run download or account requirement. Build hosts need CMake and a compatible C/C++ compiler; end users do not.

The comparison Gemma 3 4B Q4_K_M candidate is 2,489,757,856 bytes, source `https://huggingface.co/ggml-org/gemma-3-4b-it-GGUF/resolve/d0976223747697cb51e056d85c532013931fe52e/gemma-3-4b-it-Q4_K_M.gguf`, SHA-256 `882e8d2db44dc554fb0ea5077cb7e4bc49e7342a1f0da57901c0802ea21a0863`. It is benchmark-only and is not bundled. Only replace the default after checking quality and measured resource results; file size alone is not a memory benchmark.

## Redistribution

The bindings are dual MIT/Apache-2.0; this distribution elects MIT. llama.cpp is MIT. Both full MIT notices are included in the resource directory. Gemma is governed by its own terms, not MIT or Apache. The full official terms and prohibited-use policy, retrieved on 2026-10-19, are included as `GEMMA_TERMS.txt` and `GEMMA_PROHIBITED_USE_POLICY.txt`, along with the required `NOTICE`. The quantization is marked as a modification. The coach displays the complete model terms/restrictions and requires explicit acceptance before model inference. Acceptance is recorded locally for the pinned model version; the backend also receives the acceptance flag. Computed telemetry coaching remains available without model use. Redistributors must preserve the terms, notice, modification attribution and downstream use restrictions. ## Reproducible quality and resources

Build the benchmark once with `cargo build --manifest-path src-tauri/Cargo.toml --example coach_benchmark`, then invoke the executable directly, with networking disabled, under `/usr/bin/time -l src-tauri/target/debug/examples/coach_benchmark MODEL_PATH [cpu]`. Time output reports peak resident memory; JSON reports model/context load time, inference time, generated token count, acceleration and action-selection quality. The five cases cover entry, exit, low-RPM recovery, shift interruption and repeated faster examples with absent controls. Grammar/source validation checks factual boundaries and deterministic order independently of action-choice quality. Peak RSS includes executable and allocator overhead and is distinct from Metal's reported device allocation; macOS shared memory also complicates RSS interpretation. Cold-load measurements after another run may benefit from OS file caching. Benchmark facts belong in the result artifact, never inferred from model size. Windows build and runtime validation require a Windows host and are not implied by macOS success.

### Measured model selection

Single development runs on an Apple M3 with 16 GiB memory; OS caching, memory pressure and concurrent build activity affect latency. See [machine-readable results](offline-coach-benchmarks.json). These are bounded action-selection evaluations, not evidence that unrestricted language generation would be reliable.

| Gemma 3 4B Q4_K_M, Metal, same cases | 5/5 | 7.834 s | 2.029 s | 2.906 GB |

These historical action-selection runs passed their then-current schema/evidence validation and preserved deterministic ranking. They predate qualitative hypothesis generation and do not establish quality for the revised reasoning protocol. See the qualitative reasoning benchmark artifact for the later historical comparison, and the [redesign verification artifact](offline-coach-redesign-verification.json) for the latest protocol checks. The final CPU run took 22.675 s including 3.393 s integrity checking and 0.085 s backend initialization, under concurrent build/cancellation load. Earlier 1B wall times included 40–49 s debug hashing; SHA-256 is now optimized in development as well as release. A cancellation requested at 7,000 ms during CPU inference returned at 7,051 ms. This is observed cancellation latency, not a hard bound on individual native operations.

Select **1B**: equal measured action quality with a 806 MB download and roughly one-third the Metal RSS of 4B. A larger model adds no benefit to the enforced evidence/action vocabulary in this suite.

### Revised qualitative reasoning evaluation (2026-10-20)

The [qualitative reasoning comparison](offline-coach-reasoning-benchmarks.json) contains actual prompts, raw accepted/rejected responses, timings, and manual quality assessments for identical adversarial entry/exit, normal-braking, calculated-gear, RPM, overlap, and target-evidence cases. The revised protocol permits hypotheses and experiments rather than merely selecting action enums. Neither candidate demonstrated reliable engineering judgment in this small suite: the 1B sometimes generated unqualified or inverted claims that the uncertainty guard rejected; the 4B also produced poor causal advice despite schema-valid output. Keep the packaged 1B and deterministic fallback. A schema pass is not a coaching-quality pass.

A full service run on Purdue GP recording `0362.xrk` exercised the complete section-context package: 10 valid laps, 11 sections, fastest lap 26.585 s, five qualified deterministic findings, and one validated local-model explanation in 13.710 s for the explanation stage. Its hypothesis suggested an entry/exit compromise, with a calmer-entry experiment and combined corner/straight validation. It supplied no numerical gain. This demonstrates useful qualified output and a fitting context for this recording; it does not establish reliable open-ended reasoning or unrestricted causal correctness. Candidate timings are single development runs, not latency guarantees. The model remains offline and unchanged.

### Native packaged verification and maintenance

The Apple Silicon optimized `.app` bundles the model, both runtime licenses, Gemma terms/policy and manifest under `Contents/Resources/resources/coach/`. `codesign --verify --deep --strict` checks its ad hoc signature; `otool -L` shows system frameworks/libraries only, including Metal/Accelerate, with no installed llama service or external model runtime dependency.

`npm run build:mac` uses `scripts/build-macos-offline.mjs`: Tauri builds the standard branded `.app`, then clean staging strips incidental filesystem metadata and creates an APFS compressed DMG with the app and Applications shortcut. The helper verifies the source/staged app and mounts the completed image read-only for strict signature verification before publishing the local artifact. This avoids HFS Finder metadata observed invalidating the installed app signature on the development host. APFS is supported by the existing macOS 13+ floor. Windows retains its existing NSIS packaging path.

Run the built application's explicit self-check without opening or modifying the user's library:

```sh
"src-tauri/target/aarch64-apple-darwin/release/bundle/macos/Ten Tenths Telemetry.app/Contents/MacOS/apex-telemetry" \
  --coach-self-check "data/recording.xrk" --accept-gemma-terms
```

For acceptance, require `mode: localModel`, `modelResourceFound: true`, and at least one validated explanation; a recording with no meaningful findings does not exercise inference. The command parses the real XRK, runs the same deterministic engine and explanation service against the fixed packaged weights, and prints only a small diagnostic summary.

The packaged optimized application completed this check in the network-restricted sandbox: 10 valid laps, two conservative findings, two validated local-model explanations, fixed resource found, 9.103 s explanation stage from the final read-only APFS installer. This exercises CPU fallback when the sandbox withholds Metal access. Model inference runs without opening the user's persistent application library. Strict signature verification passed for both the source `.app` and the app mounted from the final APFS DMG. The `.app` and DMG packaging use the existing ad hoc signature; this feature does not add notarization or claim testing on every supported macOS version.

Focused checks are `cargo test --manifest-path src-tauri/Cargo.toml coach:: --lib`, `npm test -- --run src/coach src/workspace.test.ts`, and `npm run test:coach:premium` (local ignored XRK required). The browser check uses real Rust analysis with simulated IPC, including missing optional footage, responsiveness during held inference, stale cancellation, automatic fastest-lap selection, and dark/light layouts down to 600 px. It does not replace native WebView GUI acceptance. Native Windows compilation, installer and physical GUI acceptance still require a Windows host; no new Windows pass is claimed here. Existing Windows build commands and CI remain present, with explicit build-time model provisioning.

For a read-only fastest-lap-only diagnostic, run `cargo run --offline --manifest-path src-tauri/Cargo.toml --example coach_check -- "data/recording.xrk" --best-only`. This removes comparison laps from the in-memory session and emits the same deterministic report and plot mappings. Add `--explain --accept-gemma-terms` to exercise the bundled local model without persisting acceptance or changing the application library. An empty findings list is valid when no supported inefficiency is detected; it does not establish an optimal lap. Browser navigation fixtures are explicitly labeled when controlled test evidence supplements a recording with no findings.

When changing analysis logic, bump `ANALYSIS_VERSION`. When changing weights, update the pinned manifest and runtime version/digest together, verify redistribution terms/notices and rerun both model quality and native memory/latency checks. Keep the model out of Git and do not publish a bundle that bypasses the provisioning checksum preflight. Network operations belong only to the explicit build-host provisioning step.

### Physics-context qualitative protocol (2026-10-22)

Production no longer asks Gemma to select prewritten interpretation IDs. The `grounded-free-reasoning-v7` protocol accepts bounded model-authored hypothesis, driving experiment and validation text with validated evidence links. The deterministic engine supplies the estimated vehicle envelope and alternative speed-profile scenarios; all measurements and gain ranges remain outside the model. Cache identity includes this protocol version. The native runtime still checks cancellation between prefill batches and generated tokens, uses the pinned offline model, and releases model/context memory after each request.

Free language does not establish sound engineering judgment. The [fresh reasoning audit](physics-coach-reasoning-benchmarks.json) retains accepted and rejected native outputs separately from manual causal-quality assessment. Initial CPU trials on both adversarial suites failed semantic review despite passing structural and numerical validation: the model invented RPM oscillation and an unknown corner label, and suggested an interruption despite smooth supplied recovery. A regression now rejects monitoring unavailable throttle response. The guard cannot prove arbitrary causal prose true; the service retains deterministic experiments when output fails validation. These observations must not be described as reliable local race-engineering interpretation.

The stronger pinned Gemma 3 4B Q4_K_M was freshly downloaded to temporary storage, independently verified against its recorded SHA-256, and run on the identical final qualitative workloads. Both models passed structural/numeric validation on both workloads but failed manual causal-quality review on both. The 4B prioritized downstream support better in one case, yet prescribed a gear-change experiment from explicitly unreliable calculated gear and an RPM interruption despite smooth supplied recovery. Its larger footprint does not justify replacing the packaged model.
