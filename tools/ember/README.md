# Ember baseline harness

Run `node tools/ember/capture.mjs before` before UI changes only. Existing before images cause a refusal. Use `before --measure-only` for measurements without overwriting images; use `pass-a` or `after` for later captures. This local-only harness uses Vite development React, Playwright with DPR 1, reduced motion, disabled screenshot animations and hidden caret. Capture waits for fonts, real parsed telemetry, plots and two animation frames. The fixed configuration is exported by `fixture.mjs` (lap 9 primary, lap 10 comparison, GPS Speed and RPM, distance 30–350 m, cursor established by graph keyboard input).

**All IPC is simulated.** The cached `.tools/advanced-ui/0361.json` supplies the actual native diagnostic session and spatial lap comparison including delta. `.tools/coach-ui/0361.json` supplies actual coach diagnostic output. Both are private ignored inputs; do not commit them. Override their paths using `EMBER_ADVANCED_FIXTURE` and `EMBER_COACH_FIXTURE`. The simulated IPC intentionally rejects unsupported telemetry combinations rather than inventing analysis values. Library captures show the session details dialog. Workspace viewport is the primary chart utilization denominator; `mainWorkspace` and `mainUtilization` are supplemental. Visible row heights are clipped to the workspace and browser viewport.

The DevTools hook counts component updates approximated by changed props/state on committed fibers; it is not React Profiler timing. The interaction check compares canvas DOM identities around cursor keys and theme switching. Axe checks HTML only; canvas requires independent color contrast checks. `contrast.mjs` implements WCAG sRGB relative luminance for opaque colors; composite translucent colors against the actual surface before passing them. Screenshots and local cached inputs are never checked into source control.

Run `node tools/ember/capture.mjs after` for the final six Telemetry captures, then `node tools/ember/verify.mjs` for axe, actual canvas palette/dash readback, stationary cursor theme regression, WCAG token contrast, keyboard/zoom/pan/reset identities, 600×500 control/menu reachability, CDP CVD captures and pixelmatch diagnostics. Verification-only dependencies are isolated: `npm ci --prefix tools/ember --ignore-scripts`. `check-baseline-workflow.mjs` can reproduce the existing workflow suite against starting sources through a test-only Vite transform without changing production files. Do not run baseline measurement/capture commands after UI changes; the frozen JSON/images describe the starting commit.


Pass B.1 reuses the same deterministic fixture: `node tools/ember/capture.mjs pass-b1` captures six Telemetry images under `docs/ember/screenshots/after/pass-b1/` and writes `pass-b1-measurements.json`; `node tools/ember/verify.mjs --pass-b1` writes `pass-b1-verification.json` and pixel diffs against the Pass B images. It checks chart utilization and height against the existing Pass B measurements and records chart, sidebar and inspector bounds (the saved pre-edit audit includes reconstructed Pass B bounds at all three viewports). The copy audit counts visible direct-text owners intersecting the viewport and clipping ancestors; it includes visible aria-hidden decoration, excludes visually hidden text and canvas-drawn text, and records only a small allowlist of generic examples so private recording details are not written to the audit list. Baseline audit: `pass-b1-before-measurements.json`. React counts remain approximate development-hook counts; browser media and IPC remain simulated. CVD captures are not repeated in B.1 because trace colors are unchanged.

The `pass-b1-regions` measurement-only mode uses `git show da64955` through a Vite transform for changed tracked `src/` files, without mutating the checkout or writing screenshots. Its output was merged into the pre-edit measurements after checking the original 1440 text counts matched. The supporting-copy count uses a fixed class-based definition recorded in the JSON and includes the old map guidance text; the total also counts meaningful values and visible decorative labels.

For reference matching, `node tools/ember/reference.mjs --quick` captures the dark 1672×941 screen; omit `--quick` to capture both themes at 1672×941, 1440×900, 1920×1080, and 600×500 and run accessibility and interaction checks. Pass `--reference <image.png>` to write a side-by-side PNG. `--serve` starts a localhost preview with the same fixture. Screenshots are ignored under `docs/ember/screenshots/reference/` and the report is ignored under `.tools/ember-reference/`. The frame intervals and CDP main-thread timings measure 60 automated pointer moves in instrumented development Chromium, not native or GPU performance. Fixture IPC is simulated; other lap and axis combinations require the synthetic workflow checks or native validation.

For the global material pass, run `node tools/ember/glass.mjs --baseline` before edits and `node tools/ember/glass.mjs --final` afterward. The baseline uses 2b760e8 source through a Vite transform; both use the same local 0361 diagnostic fixture. The final run compares workspace/plot bounds within one CSS pixel, compares axe findings with the baseline, inspects protected canvases and video descendants, and checks compact menus, theme, navigation and canvas identity. `--effects` runs just focused media-fallback and checkerboard displacement checks. `--performance` compares one instrumented development Chromium run per variant; it is not a native GPU benchmark. Screenshots are ignored under `docs/ember/screenshots/glass/`; reports are ignored under `.tools/ember-glass/`. The real-data fixture has no attached video, so run the separate synthetic attached-player integration suite for media lifecycle coverage.
